# ngx-mud-ui

An Angular component library implementing **MUD** — the Moldova Unified Design
system by eGov Moldova. It ships the components, icons, design tokens and
typography used across eGov products, so a product team writes features rather
than re-deriving the design system.

## What's inside

- **23 entry points** — 22 component packages plus the icon set, each importable
  on its own so you only pull in what you use.
- **178 icons** rendered by a single `<mud-icon>` component, individually
  tree-shakeable: only the icons you register reach your bundle.
- **Design tokens** — the full colour, spacing, elevation, border and typography
  scales as CSS custom properties, with a **dark theme** built in.
- **The Onest typeface**, bundled with the styles.
- **Both Angular forms systems** — every form control implements
  `ControlValueAccessor` (reactive and template-driven) *and* the signal-forms
  contract, and each also works standalone through a two-way `model()`.

Browse **Foundations** for the tokens and **Components** for the API of each
package. Every component page carries its inputs, outputs, live examples and
usage notes.

## Installation

> **Not on a public registry yet.** `ngx-mud-ui` is not published to npm, so
> install it from a build of this repository. Once it is published the usual
> `pnpm add ngx-mud-ui` will work and this section will say so.

Build the package, then install the output into your application:

```bash
# in this repository
pnpm install
pnpm build           # ng-packagr -> dist/ngx-mud-ui
```

```bash
# in your application
pnpm add file:../ngx-mud-ui/dist/ngx-mud-ui
pnpm add @angular/cdk    # peer dependency
```

To hand the package to someone else, pack it instead:

```bash
cd dist/ngx-mud-ui && npm pack     # -> ngx-mud-ui-0.0.1.tgz
```

## Global setup

**1. Load the stylesheet once.** The components apply design-system classes;
without the stylesheet they render unstyled. This also brings in the Onest
font-face declarations, whose files resolve out of the package's `assets/`
folder.

```scss
// styles.scss
@use 'ngx-mud-ui/styles/main';
```

The styles are exported under `ngx-mud-ui/styles/*`, so you can cherry-pick
instead of taking the barrel:

```scss
@use 'ngx-mud-ui/styles/abstracts/tokens';
@use 'ngx-mud-ui/styles/themes/dark';
@use 'ngx-mud-ui/styles/components/forms/chip';
```

**2. Add the CDK overlay stylesheet** if you use `ngx-mud-ui/tooltip` or
`ngx-mud-ui/select-input` — both render through a CDK overlay and need its
structural styles:

```ts
import '@angular/cdk/overlay-prebuilt.css';
```

**3. Register the icons you use** — see [Icons](#icons) below. Only needed if
you render `<mud-icon>`.

## Using a component

Every component is standalone: import the class and put it in a component's
`imports`. There is no `NgModule` to register.

```ts
import { Component } from '@angular/core';
import { MudButton } from 'ngx-mud-ui/button';
import { MudInput } from 'ngx-mud-ui/input';

@Component({
  selector: 'app-request',
  imports: [MudButton, MudInput],
  template: `
    <mud-input label="IDNP" required [(value)]="idnp" [maxLength]="13" />
    <button type="button" mudButton (click)="submit()">Continuă</button>
  `,
})
export class RequestForm {
  idnp = '';

  submit(): void {
    // …
  }
}
```

## Icons

Icons are separate exports, so the bundle only carries the ones you register.
Register them once at bootstrap:

```ts
import { provideMudIcons, alarm, arrowLeft } from 'ngx-mud-ui/icons';

bootstrapApplication(App, {
  providers: [provideMudIcons([alarm, arrowLeft])],
});
```

Then render them anywhere:

```ts
import { MudIconComponent } from 'ngx-mud-ui/icons';

@Component({
  imports: [MudIconComponent],
  template: `<mud-icon name="alarm" variant="outlined" [scale]="24" />`,
})
export class Demo {}
```

Icons default to `variant="outlined"` and `scale="24"`, take their colour from
the surrounding CSS `color`, and are decorative unless you give them an
`aria-label`. The full set is browsable under **Components → Icon**.

## Theming

Colours resolve through CSS custom properties, so light and dark are a single
attribute on the root element:

```ts
document.documentElement.setAttribute('data-theme', 'dark'); // remove it for light
```

The attribute must sit on the **root** element. Scoped theming — putting
`data-theme` on a wrapper to darken one section — is not supported, for two
reasons:

- Many semantic tokens are **chains**: `--color-link-strict-default` is declared
  on `:root` as `var(--color-text-base-default)`. CSS substitutes a custom
  property's `var()` where that property is *declared*, so the chained token has
  already baked in its light value by the time a nested wrapper remaps the base
  one. The section's links stay black on your dark band.
- Tooltips and selects render through a **CDK overlay container attached
  directly to `<body>`**, outside any wrapper, so they would keep the page
  theme regardless.

For a permanently dark band (a hero, a footer), style it with explicit colours
instead. Use the **Theme** switch in this Storybook's toolbar to preview any
story in either mode, and see **Foundations → Dark Mode** for the full
explanation.

## Forms

Form controls work with whichever system your app uses:

```html
<!-- reactive -->
<mud-input label="IDNP" [formControl]="idnp" />

<!-- signal forms -->
<mud-input label="IDNP" [formField]="form.idnp" />

<!-- standalone -->
<mud-input label="IDNP" [(value)]="idnp" />
```

With signal forms the `invalid` and `errors` inputs are bound for you, so
validation messages appear without extra wiring.
