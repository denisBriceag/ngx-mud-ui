# Date picker

Two components in one entry point: `MudDateInput`, a masked date field that
opens a calendar popover, and `MudDatePicker`, the calendar itself — usable
inline for pages that show a calendar rather than a field.

## Import

```ts
import { MudDateInput } from 'ngx-mud-ui/date-picker';
import { MudLabel } from 'ngx-mud-ui/label';
import { MudInlineMessage } from 'ngx-mud-ui/inline-message';

@Component({
  imports: [MudDateInput, MudLabel, MudInlineMessage],
  template: `
    <mud-date-input required [formControl]="dob">
      <mud-label>Data nașterii</mud-label>
      @if (dob.touched && dob.invalid) {
        <mud-inline-message variant="error">Alegeți o dată.</mud-inline-message>
      }
    </mud-date-input>
  `,
})
export class Demo {}
```

The calendar popover renders through the CDK overlay, so the overlay stylesheet
must be loaded alongside the design-system one:

```ts
import '@angular/cdk/overlay-prebuilt.css';
```

```json
"styles": ["node_modules/ngx-mud-ui/prebuilt/mud.css", "src/styles.scss"]
```

## The value is an ISO date string

Both components use `YYYY-MM-DD` strings — never `Date` objects — in every
mode. A calendar cell is a civil date, not an instant, and `Date` brings a
timezone with it:

```ts
JSON.stringify({ dob: new Date(1990, 4, 15) })
// → {"dob":"1990-05-14T21:00:00.000Z"}   ← a birthday off by one day in UTC+3
```

With ISO strings the value that leaves your form is the value the user saw.
This is also what the platform chose: `<input type="date">.value` is exactly
`YYYY-MM-DD`.

Most backends already send date-only strings, so there is nothing to convert:

```ts
dob = new FormControl<string | null>(user.dob);   // "1990-05-15"
```

When you do hold a timestamp, convert explicitly:

```ts
import { mudDateFromDate, mudDateToDate, mudToday, mudAddDays } from 'ngx-mud-ui/date-picker';

mudDateFromDate(new Date(user.dobTimestamp))  // local Y/M/D → '1990-05-15'
mudDateToDate('2026-08-27')                   // → Date at local NOON
```

`mudDateToDate` returns local noon on purpose — a DST transition can shift
midnight across a day boundary, noon cannot. Never use `new Date('2026-08-27')`
yourself: it parses as UTC midnight.

A value that is not `YYYY-MM-DD` renders as empty and logs a dev-mode warning
naming the fix, rather than being silently truncated at the `T`.

## Formats

`format` sets both the entry mask and the display order. The value stays ISO
regardless.

`placeholder` is the format pattern the user sees: shown while the field is
empty and as the ghost behind the caret while typing. It must mirror the
format's shape, with the format's separators in place and a non-digit
character everywhere else, for example `ZZ/LL/AAAA` for `DD/MM/YYYY`.
Anything else falls back to the format itself with a warning in development
builds.

## Range

`mode="range"` renders two masked inputs in one field. Completing the start
advances focus to the end; `Backspace` at the head of the end input walks back.
Two inputs rather than one control holding both dates, because two accessible
names are what makes it announce correctly.

Each input's accessible name is the field's own label **plus** the segment, so
a `<mud-date-input mode="range">` with a projected `<mud-label>Perioada</mud-label>`
announces "Perioada, start date" — composed with `aria-labelledby`, not an
`aria-label` that would throw your label away.

## Jumping to a month or year

For dates far from today, such as a birth date, set `headerStyle="dropdown"`.
The calendar header then shows a month chip and a year chip. Each opens a grid,
so the user picks a year and a month in two clicks instead of paging back month
by month. The default, `title`, shows "Month Year" as one heading.

```html
<mud-date-input headerStyle="dropdown">
  <mud-label>Data nașterii</mud-label>
</mud-date-input>
```

## Touch screens

On a phone, a calendar under the field may not fit: a field in the middle of a
long form leaves too little room above and below it. Add `touchUi` to open the
calendar as a dialog in the middle of the screen instead, like Angular
Material's `touchUi`.

The dialog sits over a dimmed backdrop and the page behind it does not scroll.
Tapping the backdrop or pressing `Escape` closes it and returns focus to the
field. Picking a date closes it, as in the normal calendar. With `touchUi`, the
header shows the month and year chips unless you set `headerStyle` yourself.

`touchUi` never switches on by itself. To use it on small screens only, bind it
to a media query:

```ts
import { BreakpointObserver } from '@angular/cdk/layout';
import { toSignal } from '@angular/core/rxjs-interop';
import { map } from 'rxjs';

readonly touch = toSignal(
  inject(BreakpointObserver)
    .observe('(max-width: 640px)')
    .pipe(map((state) => state.matches)),
  { initialValue: false },
);
```

```html
<mud-date-input [touchUi]="touch()">
  <mud-label>Data nașterii</mud-label>
</mud-date-input>
```

A change to `touchUi` applies the next time the calendar opens.

## Bounds and disabled dates

`min` / `max` are inclusive ISO bounds. `disabledDates` takes an ISO array for
the holiday case; `dateFilter` takes a predicate returning `true` for a
**selectable** day, for rules like "weekdays only".

These disable days in the calendar and refuse out-of-range typed input — they
never write a `ValidationError` into your form. Validation rules stay yours, as
with every other control in this library.

An unavailable day is dimmed, takes no hover state and previews no range, so
the rule is visible and not only announced.

### What happens to a refused entry

While you type, the field commits only what it can use, so an incomplete,
impossible or out-of-bounds entry leaves `value` as `null`. On **blur** the
field settles: an entry it cannot use is replaced by the last date the field
actually held, so a refused edit neither strands rejected text on screen nor
destroys the value that was already there. Deleting the field yourself is a
deliberate "no date" and is never undone.

The calendar makes the same choice — clicking an unavailable day is a no-op
that keeps the current selection.

A range entered the other way round (later date first) is **reordered**, in
both the field and the calendar, rather than being rejected.

## The calendar on its own

`MudDatePicker` renders the calendar by itself — `appearance="flat"` drops the
card shadow for embedding inside your own surface, and it supports the same
`single` / `range` / `multi` selection modes and both header styles.

The header drills down: the title (or the month/year chips in `dropdown`
style) opens a month picker showing **short** month names, and a year picker
paging **12 years** at a time — both 4×3 grids, both one click back to the
days. Years drill into months rather than straight back to days, one choice at
a time.

## Label and messages

`MudDateInput` renders no label or message text of its own. Project a
`<mud-label>` for the visible label and any number of `<mud-inline-message>`
elements for assistive text — *you* decide when they render:

- Messages land in a field-owned `role="alert"` region wired into
  `aria-describedby`, alongside the field's own format hint; toggling one on
  announces it to screen readers.
- In range mode, the field's own label composes with each segment's own
  "Start date" / "End date" name through `aria-labelledby` — see
  [Range](#range) above.
- The field's `invalid` input drives the red border and `aria-invalid`; with
  signal forms it is bound automatically, with reactive forms bind
  `[invalid]="ctrl.invalid && ctrl.touched"`.

`MudDatePicker` renders no messages at all — it only takes `invalid` for the
destructive grid styling and `aria-invalid`, since a standalone calendar has
nowhere natural to put assistive text.

## Localization

Two independent layers:

1. **Month and weekday names** come from `Intl`, driven by the `locale` input
   (defaulting to the app's `LOCALE_ID`). `locale="ro"` alone localizes the
   calendar's names — no translation tables needed.
2. **Every UI string** — the Today button, the nav arrows, the clear button,
   the range field names, the screen-reader announcements — ships in English
   in the `MUD_DATE_LABELS` injection token and is overridden **app-wide in
   one `provideMudDateLabels` call**. Pass only the keys you change; the rest
   keep their defaults.

The month-picker grid shows **short** month names (`Aug`), derived from `Intl`.
When Intl's forms don't match your design — Romanian renders `ian.`, `feb.`
where the design wants `Ian`, `Feb` — override the names in the same token:
`monthNamesShort` fills the month-picker grid, `monthNamesLong` the header
title, the dropdown chip, the month-change announcements and the month
buttons' accessible names. Both arrays are 12 entries, January first.

The complete Romanian setup:

```ts
import { bootstrapApplication } from '@angular/platform-browser';
import { provideMudDateLabels } from 'ngx-mud-ui/date-picker';

bootstrapApplication(App, {
  providers: [
    provideMudDateLabels({
      calendar: 'Calendar',
      previousMonth: 'Luna precedentă',
      nextMonth: 'Luna următoare',
      previousYear: 'Anul precedent',
      nextYear: 'Anul următor',
      chooseMonth: 'Alegeți luna',
      chooseYear: 'Alegeți anul',
      today: 'Astăzi',
      clear: 'Șterge',
      rangeStart: 'Data de început',
      rangeEnd: 'Data de sfârșit',
      monthNamesShort: ['Ian', 'Feb', 'Mar', 'Apr', 'Mai', 'Iun', 'Iul', 'Aug', 'Sep', 'Oct', 'Noi', 'Dec'],
      monthNamesLong: [
        'Ianuarie', 'Februarie', 'Martie', 'Aprilie', 'Mai', 'Iunie',
        'Iulie', 'August', 'Septembrie', 'Octombrie', 'Noiembrie', 'Decembrie',
      ],
      formatHint: (pattern) => `Format: ${pattern}`,
      rangeStartSelected: (start) => `${start} selectat, alegeți data de sfârșit`,
      rangeSelected: (start, end) => `${start} – ${end} selectate`,
    }),
  ],
});
```

### Switching language at runtime

`provideMudDateLabels` also accepts a **signal** (or a factory returning one —
the factory runs in an injection context, so it can `inject()` your i18n
service). Every open calendar re-renders the moment the signal changes: the
strings, and — through the config's `locale` — the `Intl` month and weekday
names too. No per-instance wiring.

```ts
import { computed, inject } from '@angular/core';
import { provideMudDateLabels } from 'ngx-mud-ui/date-picker';
import type { MudDateLabels } from 'ngx-mud-ui/date-picker';

const TRANSLATIONS = {
  en: {},                                    // defaults are English
  ro: { locale: 'ro', today: 'Astăzi', clear: 'Șterge', /* …the set above… */ },
} satisfies Record<string, Partial<MudDateLabels>>;

bootstrapApplication(App, {
  providers: [
    provideMudDateLabels(() => {
      const i18n = inject(I18nService);       // exposes lang: Signal<'en' | 'ro'>

      return computed(() => TRANSLATIONS[i18n.lang()]);
    }),
  ],
});
```

Locale precedence for the `Intl` names: a component's own `locale` input, then
the config's `locale`, then the app `LOCALE_ID`.

`firstDayOfWeek` defaults to 1 (Monday), matching the Romanian and wider
European convention.
