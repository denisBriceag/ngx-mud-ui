# Text input

The single-line text field: optional leading and trailing icons and a clear
button, with the label and any assistive or error messages projected as
`<mud-label>` / `<mud-inline-message>` content the consumer controls. Works
standalone via `[(value)]`, with reactive and template-driven forms, and with
signal forms.

## Import

```ts
import { MudTextInput } from 'ngx-mud-ui/text-input';
import { MudLabel } from 'ngx-mud-ui/label';
import { MudInlineMessage } from 'ngx-mud-ui/inline-message';

@Component({
  imports: [MudTextInput, MudLabel, MudInlineMessage],
  template: `
    <mud-text-input required [formControl]="idnp" [maxLength]="13">
      <mud-label>IDNP</mud-label>
      @if (idnp.touched && idnp.invalid) {
        <mud-inline-message variant="error">IDNP-ul trebuie să conțină 13 cifre.</mud-inline-message>
      }
    </mud-text-input>
  `,
})
export class Demo {}
```

The base stylesheet must be in your app's `angular.json` `styles` once:

```json
"styles": ["node_modules/ngx-mud-ui/prebuilt/mud.css", "src/styles.scss"]
```

### Label and messages

The field renders no message text of its own. Project a `<mud-label>` for
the visible label and any number of `<mud-inline-message>` elements for
assistive text — *you* decide when they render:

- Messages land in a field-owned `role="alert"` region wired into
  `aria-describedby`; toggling one on announces it to screen readers.
- Inside a field, `mud-inline-message` is always the small size — its
  `size` input is ignored.
- The field's `invalid` input drives the red border and `aria-invalid`;
  with signal forms it is bound automatically, with reactive forms bind
  `[invalid]="ctrl.invalid && ctrl.touched"`.

## Usage tips

- **`invalid` drives visuals; a projected message supplies the text.**
  Nothing renders a message for you — pair `invalid` with an `@if`-guarded
  `<mud-inline-message variant="error">` to show one only when it should
  appear.
- **`aria-describedby` is for messages rendered outside the field.** The
  field already wires its own assistive-region id; to use only your own,
  don't project any `mud-inline-message`.
- **`pattern` accepts a string, a RegExp, or the `RegExp[]` signal forms push.**
  It is normalised internally, and only the first expression reaches the native
  `pattern` attribute.
- **`clearable` is suppressed** while the field is disabled, read-only or
  loading, so the affordance never appears on a field the user cannot edit.
- **`clearLabel` is an optional override.** It names the clear button. Unset or
  blank, the `textInput.clear` label applies (English 'Clear field'), so a
  language pack from `provideMudLabels` translates it.
