# Dialog

A modal dialog opened imperatively over `@angular/cdk/dialog`: focus-trapped,
scroll-blocking, dismissible via backdrop/Escape/close button, with the MUD
card chrome and a five-directive content vocabulary.

## Import

```ts
import { MudDialog, MudDialogRef, MUD_DIALOG_DATA } from 'ngx-mud-ui/dialog';
import {
  MudDialogTitle,
  MudDialogContent,
  MudDialogActions,
  MudDialogClose,
  MudDialogImage,
} from 'ngx-mud-ui/dialog';
```

## Service, not element

There is no `<mud-dialog>` element — like Angular Material's `MatDialog`,
`MudDialog` is an injectable (`providedIn: 'root'`) that opens a component or a
`TemplateRef` into an overlay:

```ts
@Component({ /* ... */ })
export class ProductPage {
  private readonly dialog = inject(MudDialog);

  confirmDelete(): void {
    const ref = this.dialog.open<boolean>(ConfirmComponent, { size: 'sm' });

    ref.closed.subscribe(({ result, reason }) => {
      if (result) this.delete();
    });
  }
}
```

Because there is no component to point Storybook Controls at, every story
below is a **launcher**: a button that calls `MudDialog.open(...)`. The
Playground's Controls panel is hand-wired to the config fields listed below —
there is nothing for compodoc to extract from a service, so this page
documents the config with plain tables instead of `<ArgTypes>`.

## Confirm

Title, body, and two actions closing the dialog through `[mudDialogClose]` —
the bound value becomes the `closed` result, with reason `'action'`.

```html
<h2 mudDialogTitle>Ștergeți documentul?</h2>
<div mudDialogContent>Acțiunea nu poate fi anulată.</div>
<div mudDialogActions>
  <button mudButton="outlined" [mudDialogClose]="false">Anulează</button>
  <button mudButton color="destructive" [mudDialogClose]="true">Șterge</button>
</div>
```

## With image

A hero image via `[mudDialogImage]`. The directive only supplies full-bleed
plumbing (`display: block; width: 100%; object-fit: cover`) — **height is the
consumer's decision**. Figma's recommendation is **280px on desktop, 180px on
mobile**; set it inline or in your own stylesheet:

```html
<img mudDialogImage src="…" alt="" style="height: 280px" />
```

The image must be the first child: the close button is absolutely positioned
and overlays it.

<Canvas of={DialogStories.WithImage} />

## Stacked actions

`[mudDialogActions]` takes a `layout` input: `'inline'` (default, right-aligned
row) or `'stacked'` (full-width buttons in a column). Either way, keep the DOM
order **secondary action first, primary last** — stacked uses
`flex-direction: column-reverse` to put the primary on top without any
reordering, and the same layout activates automatically below the 480px
breakpoint regardless of `layout`.

<Canvas of={DialogStories.StackedActions} />

## Long content

`[mudDialogContent]` is the *only* scroll region: when the card hits its
height cap, the image, title, and actions stay pinned and just the body
scrolls. A long `[mudDialogTitle]` clamps at **3 lines** (upstream clamps at
2 — a deliberate divergence).

## From a TemplateRef

`MudDialog.open()` accepts a `TemplateRef` in place of a component type.
`config.data` arrives as the template's implicit context variable, and
directives placed inside the template (including `[mudDialogClose]`) resolve
the same `MudDialogRef` a component would receive.

```html
<ng-template #tpl let-data>
  <h2 mudDialogTitle>Distribuiți acest raport</h2>
  <div mudDialogContent>… "{{ data.reportName }}" …</div>
  <div mudDialogActions>
    <button mudButton="outlined" [mudDialogClose]="undefined">Închide</button>
  </div>
</ng-template>
```

```ts
this.dialog.open(this.tpl(), { data: { reportName: 'Raport T3 2026' } });
```

## API

### `MudDialog.open(componentOrTemplate, config?)`

```ts
open<R = unknown, D = unknown>(
  componentOrTemplate: ComponentType<unknown> | TemplateRef<unknown>,
  config?: MudDialogConfig<D>,
): MudDialogRef<R>;
```

Returns a `MudDialogRef<R>` synchronously; the same instance is also
injectable inside the opened component/template.

### `MudDialogConfig<D>`

<table>
  <thead>
    <tr><th>Field</th><th>Default</th><th>Notes</th></tr>
  </thead>
  <tbody>
    <tr><td><code>data?: D</code></td><td>—</td><td>Injected via <code>MUD_DIALOG_DATA</code> (components) or as the template's implicit context (templates).</td></tr>
    <tr><td><code>size?: 'sm' | 'md' | 'lg'</code></td><td><code>'md'</code></td><td>Width rung: 480 / 588 / 720px. Mobile is always <code>min(350px, 100vw - 32px)</code> regardless of rung.</td></tr>
    <tr><td><code>showCloseButton?: boolean</code></td><td><code>true</code></td><td>Renders the container-owned × button.</td></tr>
    <tr><td><code>closeLabel?: string</code></td><td>—</td><td>Accessible name of the × button. Unset, it uses the <code>dialog.close</code> label.</td></tr>
    <tr><td><code>closeOnBackdrop?: boolean</code></td><td><code>true</code></td><td>Closes the dialog on a backdrop click. Turn it off for a form, so a stray click outside can't discard what was typed.</td></tr>
    <tr><td><code>closeOnEscape?: boolean</code></td><td><code>true</code></td><td>Closes the dialog on Escape. Turn both off when the user must answer; then only the × and your own buttons close it.</td></tr>
    <tr><td><code>ariaLabel?: string</code></td><td>—</td><td>Accessible name when the dialog has no <code>mudDialogTitle</code>.</td></tr>
    <tr><td><code>autoFocus?</code>, <code>restoreFocus?</code></td><td>CDK defaults</td><td>Passthrough to <code>@angular/cdk/dialog</code>.</td></tr>
  </tbody>
</table>

There are no width/height/maxHeight fields — the card's height is always
library-enforced (see Long content above). `panelClass` remains available as
an unsanctioned CDK escape hatch but is not documented further here.

### `MudDialogRef<R>`

- `close(result?: R, reason?: MudDialogCloseReason): void`
- `closed: Observable<{ result: R | undefined; reason: MudDialogCloseReason }>`
- `backdropClick: Observable<MouseEvent>`

### Close reasons

<table>
  <thead>
    <tr><th>Reason</th><th>Trigger</th></tr>
  </thead>
  <tbody>
    <tr><td><code>'backdrop'</code></td><td>Clicking the scrim (unless <code>closeOnBackdrop</code> is <code>false</code>).</td></tr>
    <tr><td><code>'escape'</code></td><td>Pressing Escape (unless <code>closeOnEscape</code> is <code>false</code>).</td></tr>
    <tr><td><code>'close-button'</code></td><td>Clicking the container's × (governed by <code>showCloseButton</code>, independent of <code>closeOnBackdrop</code> and <code>closeOnEscape</code>).</td></tr>
    <tr><td><code>'action'</code></td><td><code>[mudDialogClose]</code>, or a programmatic <code>ref.close()</code> with no reason given.</td></tr>
  </tbody>
</table>

A system-initiated close — navigation away, `Dialog.closeAll()`, or the
service being destroyed — bypasses `MudDialogRef.close()` entirely, so it also
reports reason `'action'`.

Dismissals without a result (×, backdrop, Escape) emit
`{ result: undefined, reason }` — check `result === undefined` to treat them
all as a cancel.

### Subscription lifecycle

You do not need to unsubscribe from `MudDialogRef`'s observables. `closed`
emits exactly once and then **completes** (same contract as Material's
`afterClosed()`), and `backdropClick` completes when the dialog's overlay is
disposed — a completed observable releases its subscribers, so nothing leaks.

The one edge case: completion happens when *the dialog* closes, not when
*your component* is destroyed. If the subscribing component can die while the
dialog stays open and the callback touches component state, guard it with
`ref.closed.pipe(takeUntilDestroyed(this.destroyRef))`. For the normal
open-and-await-outcome flow, a bare `.subscribe()` is correct.

## Accessibility

- CDK supplies the focus trap, focus restore, `role="dialog"`,
  `aria-modal="true"`, Escape handling, and scroll blocking — none of it is
  reimplemented here.
- A projected `mudDialogTitle` wires its auto-generated id into the
  container's `aria-labelledby`. For a title-less dialog, set
  `config.ariaLabel` instead so the dialog still has an accessible name.
- **The × button's only accessible name** is `config.closeLabel`, or the
  `dialog.close` label (English `'Close'`) when it is unset, so a language pack
  from `provideMudLabels` translates it. The dialog is opened from the service, so it reads the
  app-level labels; a `provideMudLabels` in one component's `providers` does not reach it.
- The hero image is presentational; the consumer owns `alt` (leave it empty
  for decorative heroes, as in the With image example above).
### Initial focus

Where focus lands on open is **the consumer's decision** via `config.autoFocus`
(a straight CDK passthrough). The library only supplies the fallback: with the
defaults (`showCloseButton: true`, `autoFocus: 'first-tabbable'`), the × is
the first tabbable element in the container, so initial focus lands there.

```ts
// Focus a specific control — any CSS selector inside the dialog:
this.dialog.open(ConfirmComponent, { autoFocus: '.confirm-cancel' });

// Focus the dialog surface itself (screen readers announce the title first):
this.dialog.open(NoticeComponent, { autoFocus: 'dialog' });

// Focus the first heading — useful for long, text-heavy dialogs:
this.dialog.open(TermsComponent, { autoFocus: 'first-heading' });
```

For confirm dialogs, the APG pattern recommends focusing the least destructive
action — `autoFocus: '.your-cancel-button-class'` is the one-liner for it.
