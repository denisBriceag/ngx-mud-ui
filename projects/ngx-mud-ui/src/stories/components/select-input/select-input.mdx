# Select input

A single-select dropdown driven by an `options` array, with the same label,
helper and error treatment as the other fields. The listbox renders in a CDK
overlay.

## Import

```ts
import { MudSelectInput } from 'ngx-mud-ui/select-input';
import type { MudSelectOption } from 'ngx-mud-ui/select-input';
import { MudLabel } from 'ngx-mud-ui/label';
import { MudInlineMessage } from 'ngx-mud-ui/inline-message';

@Component({
  imports: [MudSelectInput, MudLabel, MudInlineMessage],
  template: `
    <mud-select-input required [options]="raions" [formControl]="raion">
      <mud-label>Raion</mud-label>
      @if (raion.touched && raion.invalid) {
        <mud-inline-message variant="error">Alegeți un raion.</mud-inline-message>
      }
    </mud-select-input>
  `,
})
export class Demo {
  readonly raions: readonly MudSelectOption<string>[] = [
    { value: 'ch', label: 'Chișinău' },
    { value: 'bl', label: 'Bălți' },
  ];
}
```

The base stylesheet must be in your app's `angular.json` `styles` once:

```json
"styles": ["node_modules/ngx-mud-ui/prebuilt/mud.css", "src/styles.scss"]
```

### Label and messages

The field renders no message text of its own. Project a `<mud-label>` for
the visible label and any number of `<mud-inline-message>` elements for
assistive text — *you* decide when they render:

- Messages land in a field-owned `role="alert"` region wired into
  `aria-describedby` on the trigger; the overlay listbox itself also uses the
  same label for its `aria-labelledby`/`aria-label` pair, so a projected
  `mud-label` names both the trigger and the panel.
- Inside a field, `mud-inline-message` is always the small size — its
  `size` input is ignored.
- The field's `invalid` input drives the destructive variant and
  `aria-invalid`; with signal forms it is bound automatically, with reactive
  forms bind `[invalid]="ctrl.invalid && ctrl.touched"`.

## Usage tips

- **`options` is data, not projected content.** There is no `mud-option`
  element — build the array and let the component render it.
- **The component is generic in the option value**, so options can carry numbers
  or objects, not just strings. The selected value keeps its type.
- **`open` is two-way bindable**, which is what makes "open the dropdown when
  the user lands here" possible without reaching into the component.
- **`emptyText` shows inside the panel** when `options` is empty. It defaults to
  the English `'No options'` — localize it, and prefer it over hiding the field
  entirely so the user can see the control exists.
- **`readonly` keeps the trigger focusable but the listbox shut**, which is the
  right state for a value the user may read and copy but not change.
