# Radio

A single-choice group. `mud-radio-group` owns the value and the form binding;
each `mud-radio` contributes one option and derives its checked state from the
group.

## Import

```ts
import { MudRadio, MudRadioGroup } from 'ngx-mud-ui/radio';
import { MudLabel } from 'ngx-mud-ui/label';
import { MudInlineMessage } from 'ngx-mud-ui/inline-message';

@Component({
  imports: [MudRadio, MudRadioGroup, MudLabel, MudInlineMessage],
  template: `
    <mud-radio-group [formControl]="method" required>
      <mud-label>Metoda de plată</mud-label>
      <mud-radio value="card">
        <mud-label>Card bancar</mud-label>
      </mud-radio>
      <mud-radio value="mpay">
        <mud-label>MPay</mud-label>
        <mud-inline-message hideIcon>Fără comision.</mud-inline-message>
      </mud-radio>
      @if (method.touched && method.invalid) {
        <mud-inline-message variant="error">Alegeți o metodă de plată.</mud-inline-message>
      }
    </mud-radio-group>
  `,
})
export class Demo {}
```

The base stylesheet must be in your app's `angular.json` `styles` once:

```json
"styles": ["node_modules/ngx-mud-ui/prebuilt/mud.css", "src/styles.scss"]
```

### Label and messages

Neither component renders message text of its own. Project a `<mud-label>`
for the visible label and any number of `<mud-inline-message>` elements for
assistive text — *you* decide when they render, and where they land depends
on where you nest them:

- A `<mud-label>`/`<mud-inline-message>` projected **directly under
  `mud-radio-group`** belongs to the group: the label becomes the group's
  legend and messages land in the group's `role="alert"` region wired into
  its `aria-describedby`.
- The same elements projected **inside a `mud-radio`** belong to that option
  only: its label associates with just that native input, and its messages
  land in a wrapper scoped to that radio — with **no `role`**, since a single
  radio has no invalid state of its own; only the group is ever marked
  invalid.
- The `invalid` input on the group drives the destructive visuals on every
  child + `aria-invalid`; with signal forms it is bound automatically, with
  reactive forms bind `[invalid]="ctrl.touched && ctrl.invalid"`.

## Usage tips

- **A radio cannot be used outside a group.** Checked state derives from the
  group's value, so a lone `mud-radio` has no source of truth. For a single
  on/off choice use `mud-checkbox` or `mud-switch`.
- **Values are compared with `Object.is`**, so object and array values must be
  the same reference — rebuilding the options array each change detection cycle
  silently breaks selection. Primitives and enum values are safest.
- **`size` is set on the group**, not per option, and applies to every child.
- **Per-option `disabled` stacks with the group's.** A radio is disabled if
  either it or its group says so; disabling the group does not clear child
  settings.
- **`readonly` keeps the options focusable** but prevents the selection from
  changing, which `disabled` does not — disabled options leave the tab order.
