# Localization

Every text the library puts on screen, or says to a screen reader, can be translated. This
covers button names, announcements, empty states and the month names in a calendar. English is the
default. Romanian and Russian packs ship with the library, and you can supply your own words or
connect your translation library.

Use the buttons to switch the language of everything below. The banner message, the field labels and
the city names are the demo's own texts, translated by the demo the way your app would. The library's
texts switch on their own: open the "Locality" list to see its empty message, open the calendar, or
look at the file size and the page buttons. Some library texts are only heard, such as the banner's
"Close" button and the file's "Remove file" button.

## What the library translates

The library translates the text it owns:

- **Accessible names** of its own buttons, such as "Close", "Clear" and "Next month".
- **Announcements** read by screen readers, such as "3 files added".
- **Built-in messages**, such as "No results" in a select.
- **Formats**: month and weekday names, number formats, file sizes and page numbers.

Everything you put in is yours to translate: projected `<mud-label>` and `<mud-inline-message>`
content, placeholders, option labels, table headers, dialog and toast content, and any `aria-label`
you set yourself.

## Choosing a language pack

Add the pack for your language once, in your application config. Each pack is a complete set of
texts.

```ts
import { bootstrapApplication } from '@angular/platform-browser';
import { MUD_LABELS_RO, provideMudFormatLocale, provideMudLabels } from 'ngx-mud-ui/i18n';

bootstrapApplication(App, {
  providers: [provideMudLabels(MUD_LABELS_RO), provideMudFormatLocale('ro-MD')],
});
```

The library ships `MUD_LABELS_EN`, `MUD_LABELS_RO` and `MUD_LABELS_RU`. You don't need the English
pack, because English is what you get without one.

A pack changes words only. Dates, numbers and sizes follow the formatting locale, so set that too.
See [Dates, numbers and the formatting locale](#dates-numbers-and-the-formatting-locale).

## Changing a few words

`provideMudLabels` takes any number of arguments and merges them from left to right, one namespace
at a time. Put a pack first, then the keys you want to change.

```ts
provideMudLabels(MUD_LABELS_RO, {
  banner: { close: 'Închide mesajul' },
  pagination: { pageAria: (page, total) => `Pagina ${page} din ${total}` },
});
```

List only the keys you change. A key you leave out keeps the value from the arguments before it,
and then the English text. A text that carries a value, like the page number above, is a function
that receives that value and returns the text.

Call `provideMudLabels` once per injector (one `providers` array) and pass everything as arguments. A
second call in the same `providers` array replaces the first instead of merging with it.

Each namespace is named after its component, for example `banner`, `datePicker` or `fileInput`.
[Every key per component](#every-key-per-component) lists them all.

## Using your translation library

`provideMudLabels` also accepts a function. The function runs in an injection context, so it can
`inject()` your translation service. Return a signal and the library re-reads it when the language
changes.

**Transloco**

```ts
provideMudLabels(() => {
  const transloco = inject(TranslocoService);
  const lang = toSignal(transloco.langChanges$, { initialValue: transloco.getActiveLang() });

  return computed(() => {
    lang();

    return {
      banner: { close: transloco.translate('mud.banner.close') },
      chip: { remove: (label: string) => transloco.translate('mud.chip.remove', { label }) },
    };
  });
});
```

**ngx-translate**

```ts
provideMudLabels(() => {
  const translate = inject(TranslateService);
  const lang = toSignal(translate.onLangChange.pipe(map((event) => event.lang)), {
    initialValue: translate.currentLang,
  });

  return computed(() => {
    lang();

    return {
      banner: { close: translate.instant('mud.banner.close') },
      chip: { remove: (label: string) => translate.instant('mud.chip.remove', { label }) },
    };
  });
});
```

**Angular i18n (`$localize`)** builds one bundle per language, so a plain object is enough.

```ts
provideMudLabels({
  banner: { close: $localize`:@@mud.banner.close:Close` },
  chip: { remove: (label) => $localize`:@@mud.chip.remove:Remove ${label}:label:` },
});
```

To keep the library's packs for the keys you don't translate, put a pack first:
`provideMudLabels(MUD_LABELS_RO, () => …)`. Later arguments win.

## Switching language at runtime

Pass a signal, or a function that returns one, to both `provideMudLabels` and
`provideMudFormatLocale`. Every component on screen updates at once, with no per-component wiring.

```ts
@Injectable({ providedIn: 'root' })
export class LanguageService {
  readonly lang = signal<'en' | 'ro' | 'ru'>('en');
}

const LOCALES = { en: 'en-US', ro: 'ro-MD', ru: 'ru-RU' } as const;

bootstrapApplication(App, {
  providers: [
    provideMudLabels(() => {
      const { lang } = inject(LanguageService);

      return computed(() => (lang() === 'ro' ? MUD_LABELS_RO : lang() === 'ru' ? MUD_LABELS_RU : {}));
    }),
    provideMudFormatLocale(() => {
      const { lang } = inject(LanguageService);

      return computed(() => LOCALES[lang()]);
    }),
  ],
});
```

The demo at the top of this page does the same with one signal inside the component's `providers`.
An empty object means "no overrides", so English applies.

## A different language in one part of the app

Add `provideMudLabels` to the `providers` of one component and its subtree reads those texts. The
nested provider merges onto its parent, so you only list what differs.

```ts
@Component({
  selector: 'app-russian-section',
  providers: [provideMudLabels(MUD_LABELS_RU), provideMudFormatLocale('ru-RU')],
  template: `<mud-pagination [length]="200" />`,
})
export class RussianSection {}
```

The component's own overlays follow it: a select's panel, the calendar, a tooltip, a menu and the
phone input's country list.

**Toasts and dialogs are the exception.** They open from a service, so they read the app-level
`provideMudLabels`, not a component's. To name the close button of one toast or dialog, pass
`closeLabel` in its config.

## One instance

Most texts also have an input, so one field can say something different. An input always beats the
labels.

```html
<mud-banner closable closeLabel="Ascunde">…</mud-banner>
```

- **Blank means unset.** An empty string, or only spaces, falls back to the labels, so a button is
  never left without a name.
- **Two texts keep the empty string.** `notificationLabel=""` on a badge makes the dot decorative,
  with no role and no name. `fileListLabel=""` on a file input leaves the file list unnamed.
- **A text that carries a value is a function.** `removeLabel` on a chip, an input chip, a file
  input and a file item, `cancelLabel` on a file item, and `countryLabel(name, dialCode)` on a
  phone input all take one. `formatsCaption` on a file input receives the list of formats as a
  `readonly string[]`.

```ts
readonly removeLabel = (name: string): string => `Elimină ${name}`;
```

```html
<mud-chip type="input" removable [removeLabel]="removeLabel" label="Ana Rusu">Ana Rusu</mud-chip>
```

## Dates, numbers and the formatting locale

Formatting is separate from the words. A format locale decides month and weekday names, number
digits and separators, file sizes, page numbers, the badge's "99+" and the counters in text fields.
Each component looks for it in this order:

1. The component's own `locale` input, on the components that have one.
2. `provideMudFormatLocale(...)`.
3. Angular's `LOCALE_ID`.

```ts
provideMudFormatLocale('ro-MD');
```

A language pack never changes formatting, and a format locale never changes words. Set both. An
invalid or blank locale tag is ignored. A nested `provideMudFormatLocale` then falls back to the
locale of the provider above it, and the root one falls back to `LOCALE_ID`.

The numeric input needs care. It groups digits (`1.250,5`) only when its own `locale` input is set.
Without it, it shows the number in the format locale's decimal style (`1250,5`) and reads that
locale's own digits back.

## Every key per component

This is every text in `MudLabels`, with the English value. A name in braces, such as `{name}`, marks where a value goes.
Functions receive the values named at the end of each line.

### Banner

- `close`: `Close`

### Breadcrumb

- `navigation`: `Breadcrumb`
- `overflow`: `Show collapsed pages`

### Chip

- `remove`: `Remove {label}` (function of `label`)

### Date picker

Namespace `datePicker`.

- `calendar`: `Calendar`
- `previousMonth`: `Previous month`
- `nextMonth`: `Next month`
- `previousYear`: `Previous year`
- `nextYear`: `Next year`
- `chooseMonth`: `{month}, Choose month` (function of `month`)
- `chooseYear`: `{year}, Choose year` (function of `year`)
- `today`: `Today`
- `clear`: `Clear`
- `rangeStart`: `Start date`
- `rangeEnd`: `End date`
- `formatHint`: `Date format: {pattern}` (function of `pattern`)
- `monthChanged`: `{monthYear}` (function of `monthYear`)
- `rangeStartSelected`: `{start} selected, choose end date` (function of `start`)
- `rangeSelected`: `{start} to {end} selected` (function of `start`, `end`)
- `monthNamesShort` and `monthNamesLong`: optional lists of 12 names, January first. Unset, the names come from Intl. They are the only pack keys that override Intl's month names; everything else that is formatted (dates, numbers, country names) comes from the formatting locale.
