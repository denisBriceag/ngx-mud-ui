# Info Box Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a `ngx-mud-ui/info-box` entry point containing `MudInfoBox` — an inline in-content callout with five variants, an optional heading, a projected action region and an optional close button.

**Architecture:** One display component with an inline template, modelled on the `banner` and `inline-message` siblings: inlined default glyph per variant overridable by projection, `_hostClasses` computed bound to `host: { '[class]': … }`, no forms protocol, no overlay, never a live region.

**Tech Stack:** Angular 22 (zoneless, signals, `input()`/`output()`, OnPush), SCSS partial in the shared styles tree, Vitest via `ng test`, Storybook stories + MDX.

**Spec:** `docs/superpowers/specs/2026-08-30-info-box-design.md`

## Global Constraints

- **DO NOT COMMIT ANYTHING. DO NOT STAGE ANYTHING.** No `git commit`, no `git add`, no `git add -N`, no branch or HEAD changes. HEAD stays at `d50485b`. The user commits this work themselves. Every task ends with a verification step, not a commit. (`git checkout -- <file>` to revert one file is permitted; nothing else touching git state is.)
- Angular 22, zoneless, `ChangeDetectionStrategy.OnPush`, standalone-by-default (do NOT write `standalone: true`), signals only.
- ESLint enforces `_`-prefixed private/protected members.
- Template control flow is `@if` / `@switch`.
- `vi`, `describe`, `it`, `expect` are Vitest globals — do NOT import them from `vitest`.
- Tests need Node 24: `source ~/.nvm/nvm.sh && nvm use 24` first, in the same shell invocation.
- **Never a live region.** No `role`, no `aria-live`, under any input combination. This is static in-flow content; a live region would re-announce on every render.
- **`aria-label` must not be inert.** An `aria-label` on a role-less element is ignored by assistive technology, so a labelled host takes `role="region"`.
- Every colour a semantic `--color-*` token. Radii carry literal fallbacks (`var(--border-radius-8, 8px)`) — `--border-radius-*` and `--drop-shadow-300` are referenced across this repo but **defined nowhere**, so a bare `var()` silently drops the property.
- `font-weight: 600` as a literal is the house idiom (eleven partials do it).
- The component NEVER removes itself from the DOM; it emits `closed` and the consumer removes it.
- `closeLabel` is a plain input with an English default — the house convention for one-off button labels. NOT an injection token.

```ts
import { booleanAttribute, ChangeDetectionStrategy, Component, computed, input, output } from '@angular/core';

export type MudInfoBoxVariant = 'neutral' | 'moderate' | 'prominent' | 'warning' | 'error';

const DEFAULT_CLOSE_LABEL = 'Close';

/**
 * Inline, in-content callout — an explanation, a prerequisite, a caution
 * attached to a section rather than to a form control. Fills its container and
 * sits in the normal page flow.
 *
 * Not to be confused with its siblings: `mud-banner` is a full-width
 * top-of-page system bar, and a toast is a transient corner surface. Unlike
 * those, an info box is NEVER a live region — it is static content, and
 * announcing it would re-fire on every render.
 *
 * ```html
 * <mud-info-box variant="prominent" heading="Before you begin" closable (closed)="hide()">
 *   You will need your IDNP and a scanned copy of your passport.
 *   <div actions><a mudLink href="/help">Read the guide</a></div>
 * </mud-info-box>
 * ```
 */
@Component({
  selector: 'mud-info-box',
  template: `
    @if (!hideIcon()) {
      <span class="info-box__icon" aria-hidden="true">
        <ng-content select="mud-icon,svg">
          @switch (variant()) {
            @case ('warning') {
              <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 20 20" fill="currentColor" focusable="false">
                <path
                  fill-rule="evenodd"
                  clip-rule="evenodd"
                  d="M8.563 3.31a1.667 1.667 0 0 1 2.874 0L18.313 15c.654 1.11-.148 2.512-1.437 2.512H3.124c-1.29 0-2.09-1.401-1.437-2.512zM10 8.345c.46 0 .834.373.834.833v1.667a.833.833 0 1 1-1.667 0V9.178c0-.46.373-.833.833-.833m-1.041 5a1.042 1.042 0 1 1 2.083 0 1.042 1.042 0 0 1-2.083 0"
                />
              </svg>
            }
            @case ('error') {
              <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 20 20" fill="currentColor" focusable="false">
                <path
                  fill-rule="evenodd"
                  clip-rule="evenodd"
                  d="M10 1.667a8.333 8.333 0 1 0 0 16.666 8.333 8.333 0 0 0 0-16.666m-.833 7.5c0-.459.416-.834.833-.834s.833.373.833.834v4.166a.833.833 0 0 1-1.666 0zM10 5.833A.833.833 0 1 0 10 7.5a.833.833 0 0 0 0-1.667"
                />
              </svg>
            }
            @default {
              <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 20 20" fill="currentColor" focusable="false">
                <path
                  fill-rule="evenodd"
                  clip-rule="evenodd"
                  d="M10 1.667a8.333 8.333 0 1 0 0 16.666 8.333 8.333 0 0 0 0-16.666m-1.667 7.5c0-.46.373-.834.834-.834H10c.46 0 .833.373.833.834v4.166a.833.833 0 0 1-1.666 0V10a.833.833 0 0 1-.834-.833M10 5.833A.833.833 0 1 0 10 7.5a.833.833 0 0 0 0-1.667"
                />
              </svg>
            }
          }
        </ng-content>
      </span>
    }

    <div class="info-box__body">
      @if (heading()) {
        <p class="info-box__heading">{{ heading() }}</p>
      }
      <div class="info-box__message"><ng-content /></div>
      <div class="info-box__actions"><ng-content select="[actions]" /></div>
    </div>

    @if (closable()) {
      <button type="button" class="info-box__close" [attr.aria-label]="_closeLabel()" (click)="_close()">
        <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 20 20" fill="currentColor" focusable="false" aria-hidden="true">
          <path
            fill-rule="evenodd"
            clip-rule="evenodd"
            d="M5.244 5.244a.833.833 0 0 1 1.179 0L10 8.821l3.577-3.577a.833.833 0 1 1 1.179 1.179L11.179 10l3.577 3.577a.833.833 0 0 1-1.179 1.179L10 11.179l-3.577 3.577a.833.833 0 0 1-1.179-1.179L8.821 10 5.244 6.423a.833.833 0 0 1 0-1.179"
          />
        </svg>
      </button>
    }
  `,
  host: {
    '[class]': '_hostClasses()',
    '[attr.role]': '_role()',
    '[attr.aria-label]': '_label()',
  },
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class MudInfoBox {
  /** @description Semantic treatment. `prominent` is the brand-tinted surface. */
  readonly variant = input<MudInfoBoxVariant>('neutral');

  /**
   * @description Optional bold heading above the body. Rendered as a `<p>`, NOT
   * an `<h*>` — a callout title should not inject an entry into the document
   * outline, and only you know the right level if it should. If you want a real
   * heading, put an `<h3>` in the body and leave this unset.
   */
  readonly heading = input<string | undefined>(undefined);

  /** @description Renders a trailing close button. Activating it emits `closed`. */
  readonly closable = input(false, { transform: booleanAttribute });

  /** @description Suppresses the leading icon entirely. */
  readonly hideIcon = input(false, { transform: booleanAttribute });

  /** @description Accessible name for the close button. */
  readonly closeLabel = input(DEFAULT_CLOSE_LABEL);

  /** @description Accessible name for the box itself. Gives the host a `region` role. */
  readonly ariaLabel = input<string | undefined>(undefined, { alias: 'aria-label' });

  /** Emitted when the close button is activated. The CONSUMER removes the box. */
  readonly closed = output<void>();

  /** Blank/whitespace-only does not count as a value — it would otherwise
   *  render a close button with no accessible name. */
  protected readonly _closeLabel = computed(() => this.closeLabel().trim() || DEFAULT_CLOSE_LABEL);

  protected readonly _hostClasses = computed(() => `info-box info-box--${this.variant()}`);

  /** Blank or whitespace-only is not a label — it must not produce an
   *  `aria-label` on a host that consequently has no role. */
  protected readonly _label = computed(() => this.ariaLabel()?.trim() || null);

  /**
   * `region` when the box carries a name, so the label is not inert; otherwise
   * nothing. NEVER a live region — this is static in-flow content.
   */
  protected readonly _role = computed<string | null>(() => (this._label() ? 'region' : null));

  protected _close(): void {
    this.closed.emit();
  }
}
```

Note the `[aria-label]` interaction, which is subtle: the input is aliased to `aria-label`, so a consumer binding `[aria-label]="x"` sets the **input** but puts no attribute in the DOM, while `[attr.aria-label]="x"` would set the attribute and bypass the input. The component therefore reads the input for its role decision AND reflects it back via the host binding. The test host binds `[aria-label]`, never `[attr.aria-label]`.

# Info box

An inline callout that sits **inside your content**, highlighting an

## Variants

Five, and unlike the other message components there is no separate
subtle/strong axis — each variant carries its own surface. `neutral`,
`moderate` and `prominent` share the info glyph and differ in icon colour and
background; `prominent` is the only one with a tinted surface.

## Heading

`heading` renders as a `<p>`, **not** an `<h2>`/`<h3>`. A callout title should
not add an entry to the page's document outline, and only you know the right
level if it should.

If you do want a real heading, put one in the body and leave `heading` unset:

```html
<mud-info-box variant="prominent">
  <h3>Before you begin</h3>
  You will need your IDNP.
</mud-info-box>
```

## Actions

Project them into the `actions` slot — buttons, links, with or without icons.
Nothing is configured through inputs, so a `routerLink` works exactly as it
would anywhere else.

<Canvas of={InfoBoxStories.WithActions} />

## Closing

`closable` renders a close button that emits `closed`. **The box does not remove
itself** — you own that, so it composes with `@if` in your template.

<Canvas of={InfoBoxStories.Closable} />

The close button is 32×32, growing to 40×40 on coarse-pointer devices. The ×
glyph stays 16px; only the target grows.

## Accessibility

An info box is **never** an ARIA live region. It is static content in the page
flow, so announcing it would re-fire on every render. If you need a message
announced when a condition changes, that is `mud-banner` with `live`, or your
own live region.

Setting `aria-label` gives the box a `region` role so it becomes a navigable
landmark — an `aria-label` alone, without a role, is ignored by assistive
technology.

The icon is decorative (`aria-hidden`); the text carries the meaning. `hideIcon`
removes the icon region entirely.

<Canvas of={InfoBoxStories.WithoutIcon} />

## Localization

The box owns one string — the close button's accessible name. Override it per
instance:

```html
<mud-info-box closable closeLabel="Închide">…</mud-info-box>
```

It defaults to `Close`, and a blank or whitespace value falls back to that
default rather than leaving the button unnamed. Everything else is your
projected content, so it is already in your language.

- [ ] **Step 6: Compute twenty contrast ratios — do not eyeball**

Five variants × two themes, for **both** the body text (≥ 4.5:1) and the icon (≥ 3:1, SC 1.4.11).

The light-theme values are already known and your numbers must match them:

| Variant | Text | Icon |
| --- | --- | --- |
| `neutral` | 10.76:1 | 4.23:1 |
| `moderate` | 10.76:1 | 5.79:1 |
| `prominent` | 16.31:1 | 5.50:1 |
| `warning` | 10.76:1 | **3.20:1** |
| `error` | 10.76:1 | 4.43:1 |

The dark values are the unverified half. `warning`'s icon has the least margin of any of them — it clears 3:1 by 0.2 in light, so the dark value is the one most likely to fail.

The cheapest honest method is a script in the browser-mode storybook project that renders each variant in each theme, reads `getComputedStyle` for `color` and `background-color` (and the icon's colour), and computes the WCAG ratio. If you cannot automate it, resolve the token chains by hand through `abstracts/_tokens.scss`, `abstracts/_colors.scss` and `themes/_dark.scss` and compute the ratios — then say explicitly that is what you did.
