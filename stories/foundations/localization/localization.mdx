# Localization

Every text the library shows, or says to a screen reader, can be translated: button names,
announcements, empty states, month names. English is the default. **Romanian and Russian packs
ship with the library**, and you can override any word or plug in your own translation library.

Switch the language below. The field labels, banner message and city names are the demo's own
texts. Everything else, including what only a screen reader hears, comes from the library. Open the
"Locality" list or the calendar to see more.

## Quick start

Add a pack and a formatting locale once, in your application config:

```ts
import { MUD_LABELS_RO, provideMudFormatLocale, provideMudLabels } from 'ngx-mud-ui/i18n';

bootstrapApplication(App, {
  providers: [provideMudLabels(MUD_LABELS_RO), provideMudFormatLocale('ro-MD')],
});
```

Set **both**. A pack changes words only, and the locale changes formats only (dates, numbers, file
sizes). The packs are `MUD_LABELS_EN`, `MUD_LABELS_RO` and `MUD_LABELS_RU`; you never need the
English one, since it's the default.

## Who translates what

**The library** translates the text it owns: the accessible names of its own buttons ("Close",
"Next month"), screen-reader announcements ("3 files added"), built-in messages ("No results"), and
formats such as month names, numbers and file sizes.

**You** translate everything you put in: projected `<mud-label>` and `<mud-inline-message>`
content, placeholders, option labels, table headers, dialog and toast content, and any `aria-label`
you set yourself.

## Changing a few words

`provideMudLabels` merges its arguments from left to right, one namespace at a time. Put a pack
first, then only the keys you change:

```ts
provideMudLabels(MUD_LABELS_RO, {
  banner: { close: 'Închide mesajul' },
  pagination: { pageAria: (page, total) => `Pagina ${page} din ${total}` },
});
```

A text that carries a value, like the page number above, is a function. Every key, with its text
in all three languages, is in the [label reference](#label-reference) at the bottom of this page.

Call `provideMudLabels` once per `providers` array and pass everything as arguments. A second call
in the same array replaces the first instead of merging with it.

## Using your translation library

`provideMudLabels` also takes a function that runs in an injection context, so it can `inject()`
your translation service. Return a signal and the library re-reads it when the language changes.

**Transloco**

```ts
provideMudLabels(MUD_LABELS_RO, () => {
  const transloco = inject(TranslocoService);
  const lang = toSignal(transloco.langChanges$, { initialValue: transloco.getActiveLang() });

  return computed(() => {
    lang();

    return {
      banner: { close: transloco.translate('mud.banner.close') },
      chip: { remove: (label: string) => transloco.translate('mud.chip.remove', { label }) },
    };
  });
});
```

**ngx-translate**

```ts
provideMudLabels(MUD_LABELS_RO, () => {
  const translate = inject(TranslateService);
  const lang = toSignal(translate.onLangChange.pipe(map((event) => event.lang)), {
    initialValue: translate.currentLang,
  });

  return computed(() => {
    lang();

    return {
      banner: { close: translate.instant('mud.banner.close') },
      chip: { remove: (label: string) => translate.instant('mud.chip.remove', { label }) },
    };
  });
});
```

**Angular i18n (`$localize`)** builds one bundle per language, so a plain object is enough:

```ts
provideMudLabels({
  banner: { close: $localize`:@@mud.banner.close:Close` },
  chip: { remove: (label) => $localize`:@@mud.chip.remove:Remove ${label}:label:` },
});
```

In the Transloco and ngx-translate examples, the pack in front supplies every key you don't
translate yourself. Put one in front of the `$localize` object too if you only translate some keys.

## Switching language at runtime

Pass a signal (or a function returning one) to both providers. Every component on screen updates at
once. This is exactly what the demo above does.

```ts
const LOCALES = { en: 'en-US', ro: 'ro-MD', ru: 'ru-RU' } as const;

bootstrapApplication(App, {
  providers: [
    provideMudLabels(() => {
      const { lang } = inject(LanguageService);

      return computed(() =>
        lang() === 'ro' ? MUD_LABELS_RO : lang() === 'ru' ? MUD_LABELS_RU : {},
      );
    }),
    provideMudFormatLocale(() => {
      const { lang } = inject(LanguageService);

      return computed(() => LOCALES[lang()]);
    }),
  ],
});
```

An empty object means "no overrides", so English applies.

## One section in another language

Providers nest. Add them to one component and its subtree, including its overlays (select panels,
calendars, tooltips, menus), uses those texts. A nested `provideMudLabels` merges onto its parent,
so list only what differs.

```ts
@Component({
  selector: 'app-russian-section',
  providers: [provideMudLabels(MUD_LABELS_RU), provideMudFormatLocale('ru-RU')],
  template: `<mud-pagination [length]="200" />`,
})
export class RussianSection {}
```

> **Toasts and dialogs are the exception.** They open from a service, so they read the app-level
> labels. To rename one toast's or dialog's close button, pass `closeLabel` in its config.

## One instance

Most texts also have an input that beats the labels for that one component:

```html
<mud-banner closable closeLabel="Ascunde">…</mud-banner>
```

- **Blank means unset.** An empty or whitespace-only value falls back to the labels, so a button is
  never left without a name.
- **Two inputs keep the empty string on purpose.** `notificationLabel=""` on a badge makes the dot
  decorative; `fileListLabel=""` on a file input leaves the file list unnamed.
- **Texts that carry a value take a function**, the same shape as the label key: `removeLabel` on
  chips, input chips and file items, `cancelLabel` on a file item, `countryLabel(name, dialCode)` on
  a phone input, `formatsCaption(formats)` on a file input.

## Dates, numbers and the formatting locale

The formatting locale decides month and weekday names, digits and separators, file sizes, page
numbers, the badge's "99+" and text-field counters. Each component uses the first one it finds:

1. Its own `locale` input, on components that have one.
2. The nearest `provideMudFormatLocale(...)`.
3. Angular's `LOCALE_ID`.

An invalid or blank locale tag is ignored and the next one down applies.

The numeric input groups digits (`1.250,5`) only when its own `locale` input is set. Without it, it
uses the formatting locale's decimal style (`1250,5`) without grouping.

## Label reference

Every text in `MudLabels`, generated from the shipped packs. Values in a function's text are sample
arguments. A dash means the pack doesn't set that key: the month-name lists are optional, and when
they're unset the names come from the formatting locale.
