# Dark Mode

**The library ships a dark theme, and every component supports it.** All 23
components adapt on their own: there is no dark variant to import, no
per-component input, and no JavaScript inside the components. Flip one attribute
on the page and the whole design system follows.

Use the **Theme** switch in this Storybook's toolbar to preview any story in
either mode.

## How it works

The stylesheet defines colour in three layers:

1. **Palette** — raw values such as `--mud-blue-sky-600: #0058D2`. These never change.
2. **Semantic tokens** — meanings such as `--mud-color-text-base-default`, declared
   on `:root` and pointing into the palette.
3. **Dark overrides** — the opt-in dark stylesheet (`mud-dark.css`) re-points the semantic tokens under
   `:root[data-theme='dark']`, so text turns white, surfaces turn near-black, and
   brand colours lighten enough to hold contrast.

The rule that follows: style with a **semantic token** and you get dark mode for
free; hard-code a palette value (or a hex) and you are frozen to one appearance.

## Enabling it

**1. Add the dark stylesheet.** The dark theme is opt-in and ships separately, so apps that stay
light don't load it. Add it to `angular.json` `styles` next to the base stylesheet — its `:root[data-theme='dark']`
rules out-rank the light `:root` values, so the order of the two files does not matter. `ng add ngx-mud-ui --darkMode`
adds the entry for you.

```json
"styles": [
  "node_modules/ngx-mud-ui/prebuilt/mud.css",
  "node_modules/ngx-mud-ui/prebuilt/mud-dark.css",
  "src/styles.scss"
]
```

Without it, `data-theme="dark"` simply does nothing — the page stays light.

**2. Set `data-theme` on the root element** — `document.documentElement`:

```ts
@Injectable({ providedIn: 'root' })
export class ThemeService {
  private readonly _root = inject(DOCUMENT).documentElement;

  readonly theme = signal<'light' | 'dark'>('light');

  constructor() {
    effect(() => {
      if (this.theme() === 'dark') {
        this._root.setAttribute('data-theme', 'dark');
      } else {
        this._root.removeAttribute('data-theme');
      }
    });
  }

  toggle(): void {
    this.theme.update((current) => (current === 'dark' ? 'light' : 'dark'));
  }
}
```

To honour the OS preference, seed the signal from
`matchMedia('(prefers-color-scheme: dark)').matches` (guard it for the server),
and call `theme.set(...)` from that query's `change` event to keep following it.

**3. Declare `color-scheme`** so native UI — form controls, scrollbars, the
canvas behind your page — matches:

```css
:root {
  color-scheme: light;
}
[data-theme='dark'] {
  color-scheme: dark;
}
```

**4. Paint your own surfaces with tokens.** The theme recolours tokens, not your
markup, so your app shell needs to read them too:

```css
body {
  background: var(--mud-color-background-base-default);
  color: var(--mud-color-text-base-default);
}
```

## Worth knowing

- **Some surfaces invert on purpose.** `mudButton color="strict"` and the
  tooltip bubble are inverse surfaces: dark on a light page, light on a dark
  one. That is the design, not a bug.
- **Icons follow `currentColor`**, so `<mud-icon>` adapts to whatever the
  surrounding text does without any theming of its own.

## Scoped theming is not supported

`data-theme` belongs on the root element only. Darkening one section does not
work:

```html
<!-- ❌ the link stays black -->
<div data-theme="dark">
  <a mudLink="strict" href="/terms">Terms</a>
</div>
```

Two reasons:

- **Token chains resolve where they are declared.**
  `--mud-color-link-strict-default` is declared on `:root` as
  `var(--mud-color-text-base-default)`. CSS substitutes that `var()` on `:root`, and
  descendants inherit the already-resolved colour — so remapping the base token
  further down the tree changes nothing the link reads.
- **Overlays escape the wrapper.** Tooltips and selects render into a CDK
  overlay container attached directly to `<body>`, outside any nested element,
  so they would keep the page theme regardless.

For a permanently dark band — a hero, a footer — style it with explicit colours
instead of `data-theme`.
