# Table

A data table for lists of records such as requests, payments or people. It's the CDK table with the
MUD styling and a sort shaped like Angular Material's: if you know `mat-table` and `matSort`, swap
the prefix. Everything the CDK table does (sticky rows and columns, footers, several row templates,
`trackBy`) works as usual.

```ts
import {
  MudCell,
  MudCellDef,
  MudColumnDef,
  MudHeaderCell,
  MudHeaderCellDef,
  MudHeaderRow,
  MudHeaderRowDef,
  MudRow,
  MudRowDef,
  MudSort,
  MudSortHeader,
  MudTable,
  MudTableDataSource,
} from 'ngx-mud-ui/table';
```

Every directive is standalone; import only the ones you use.

## Sorting

Put `mudSort` on the table and `mud-sort-header` on each sortable header cell. A click cycles
ascending, descending and unsorted (`disableClear` skips unsorted; `start="desc"` begins
descending). `sortChange` emits `{ active, direction }`, and both are two-way bindable. A header with
`disabled` isn't sortable.

To sort in memory, give a `MudTableDataSource` the `MudSort` after the first render. Override its
`sortingDataAccessor` for nested or computed fields, or `sortData` to replace the comparison. Empty
values always go last. To sort on the server, skip the data source and handle `sortChange`.

## Data from the server

When the server sorts, bind the rows to `[dataSource]`, keep the sort in a signal that feeds
`rxResource`, and update it from `(sortChange)`. `*mudNoDataRow` shows the loading and error states,
`aria-busy` marks the table while loading, and a live region announces the result count. The example
exports a fake backend interceptor so it runs without a server.

<Canvas of={TableStories.Http} />

## Pagination

Put a [`<mud-pagination>`](?path=/docs/components-pagination--docs) below the table and give it to
the data source's `paginator`, like the sort. The data source sorts, then shows one page, and keeps
the paginator's `length` up to date. Re-sorting keeps the current page; this example goes back to
page 1 from `(sortChange)`.

<Canvas of={TableStories.Paginated} />

## Server-side paging

For large data, the server sorts and pages. Bind the current page to `[dataSource]`, the total to
`[length]`, and `[(pageIndex)]` to a signal that feeds `rxResource` with the sort. Reset `pageIndex`
when the sort changes. The example keeps the last page in a `linkedSignal`, so the rows and page
count stay on screen while the next page loads.

## Sticky rows and columns

`sticky: true` on the header row definition, and `sticky` or `stickyEnd` on a column definition.
Wrap the table in an element with the `mud-data-table-container` class for horizontal scrolling,
and give it `tabindex="0"` so keyboard users can scroll it.

## Selection

There's no selection input: add a column with a `mud-checkbox` per row and keep the state in a CDK
`SelectionModel`. Give that column's cells the `mud-data-table__selection-cell` class (narrow width)
and bind `[selected]` on the row to highlight it and set `aria-selected`.

<Canvas of={TableStories.Selection} />

A cell can hold any component. For a status column, map each state to a

## Row actions

Put actions in a last column with `mudIconButton size="small"`, and give that column's cells the
`mud-data-table__actions-cell` class so the row stays 40px tall. Name each icon button per row, such
as `[attr.aria-label]="'Editează ' + row.nume"`.

## Accessibility

- Prefer the native `<table>`: screen readers get row and column navigation for free.
- Name the table with `aria-label` or `aria-labelledby`.
- A sortable header is a real button named by its text, with a hidden "Sort" hint
  (`sortActionDescription`, translatable). The `<th>` has `aria-sort`. Direction is shown by the
  chevron's shape, not by color.
- Give scroll containers `tabindex="0"`.
- `aria-selected` on rows isn't announced reliably outside a grid, so the per-row checkbox is what
  tells screen-reader users which rows are selected.

## Layout notes

- Every cell of a column gets the class `mud-column-<name>`; set column widths on it from your
  component, such as `.mud-column-suma { width: 120px }`.
- Everything is start-aligned, numbers included, by design.
- Cell padding shrinks from 24px to 16px on screens up to 640px.

### MudTableDataSource&lt;T&gt;

`new MudTableDataSource(rows)`, then:

- `data` (`T[]`): the rows; set it to replace them.
- `sort` (`MudSort | null`): sorts the rows in memory.
- `paginator` (`MudPagination | null`): shows one page and keeps the paginator's `length` up to date.
- `sortingDataAccessor(row, columnId)`: the value a column sorts by.
- `sortData(rows, sort)`: the whole sort; replace it for custom ordering.

### Other directives

- Cell templates: `*mudHeaderCellDef`, `*mudCellDef="let row"`, `*mudFooterCellDef`.
- Row templates: `*mudHeaderRowDef="columns; sticky: true"`,
  `*mudRowDef="let row; columns: columns; when: predicate"`, `*mudFooterRowDef="columns"`,
  `*mudNoDataRow`.
- Cells: `th[mud-header-cell]`, `td[mud-cell]`, `td[mud-footer-cell]` (or `mud-header-cell`,
  `mud-cell`, `mud-footer-cell`).
- Rows: `tr[mud-header-row]`, `tr[mud-row]`, `tr[mud-footer-row]` (or the element forms).

### Types

- `MudTableHeaderStyle`: `'subtle' | 'strong' | 'white'`
- `MudTableRowStyle`: `'default' | 'zebra'`
- `MudSortDirection`: `'asc' | 'desc' | ''`
- `MudSortState`: `{ active: string; direction: MudSortDirection }`
