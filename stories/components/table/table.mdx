# Table

A data table for lists of records — applications, payments, people. It is the
Angular CDK table with our styling and a Material-shaped sort mechanism: if you
know `mat-table` and `matSort`, swap the prefix and you are done. Everything the
CDK table can do (sticky rows and columns, footers, multiple row templates,
`trackBy`, row recycling) works unchanged.

```html
<table mud-table [dataSource]="rows" mudSort (sortChange)="reload($event)">
  <ng-container mudColumnDef="nume">
    <th mud-header-cell *mudHeaderCellDef mud-sort-header>Nume</th>
    <td mud-cell *mudCellDef="let row">{{ row.nume }}</td>
  </ng-container>
  <tr mud-header-row *mudHeaderRowDef="columns"></tr>
  <tr mud-row *mudRowDef="let row; columns: columns"></tr>
</table>
```

## Import

```ts
import {
  MudTable, MudColumnDef, MudHeaderCellDef, MudCellDef, MudHeaderCell, MudCell,
  MudHeaderRowDef, MudRowDef, MudHeaderRow, MudRow, MudSort, MudSortHeader, MudTableDataSource,

```

## Sorting

Put `mudSort` on the table and `mud-sort-header` on each sortable header cell.
The header renders a real button with the column label and a `chevron-grabber`
icon; once sorted it shows a single chevron for the direction. Clicking cycles
ascending → descending → unsorted (set `disableClear` to skip the last step,
`start="desc"` to begin descending). `sortChange` emits `{ active, direction }`,
and `active`/`direction` are two-way bindable. A header with `disabled` (or inside
a disabled `mudSort`) keeps its button but renders it disabled, without a chevron
or `aria-sort`; screen readers announce it as an unavailable button.

To sort in memory, hand a `MudTableDataSource` the sort:

```ts
readonly source = new MudTableDataSource(rows);
readonly sort = viewChild.required(MudSort);

constructor() {
  afterNextRender(() => { this.source.sort = this.sort(); });
}
```

Override `sortingDataAccessor` for nested or derived fields, or `sortData` to
replace the comparator. Empty values always sort to the bottom. For server-side
sorting skip the data source and handle `sortChange` yourself.

## Data from an HTTP request

When the server does the sorting, skip `MudTableDataSource`: bind the array to
`[dataSource]`, keep the sort state in a signal, feed it to `rxResource`, and let
`(sortChange)` update the signal so the request re-runs with `sort` and `dir`
parameters. The `*mudNoDataRow` doubles as the loading state (a `mud-spinner`) and
the error state, `aria-busy` marks the table while a request is in flight, and a
polite live region announces the result count. The story answers `/api/cereri`
from an `HttpInterceptorFn` with a 700ms delay because Storybook has no server;
the component itself is what you would ship.

## Pagination

Pair the table with `<mud-pagination>` from `ngx-mud-ui/pagination` (see the
Pagination page for its full API). Place it below the table; it is a block-level flex
container, so `justify-content: flex-end` right-aligns it.

### In memory

Give the data source the paginator, the same way as the sort. It sorts first, then
slices one page, keeps the paginator's `length` equal to the row count, and moves
back to the last page if the data shrinks under the current one.

```ts
readonly source = new MudTableDataSource(rows);
readonly sort = viewChild.required(MudSort);
readonly paginator = viewChild.required(MudPagination);

constructor() {
  afterNextRender(() => {
    this.source.sort = this.sort();
    this.source.paginator = this.paginator();
  });
}
```

Re-sorting keeps the current page, as in Angular Material. The story goes back to
page 1 with `(sortChange)="paginator().firstPage()"`; drop it if you prefer to stay.

<Canvas of={TableStories.Paginated} />

### From the server

For large datasets the server sorts and pages. Skip `MudTableDataSource`: bind the
current page's rows to `[dataSource]`, the server's total to `[length]`, and
two-way bind `[(pageIndex)]` to a signal that feeds `rxResource` together with the
sort, so a click on a page or a header re-runs the request. Reset `pageIndex` to 0
when the sort changes. `rxResource` falls back to its `defaultValue` while a new
request is in flight, so the story keeps the last page in a `linkedSignal`: the rows
stay on screen (with `aria-busy`) and the paginator keeps its page count instead of
collapsing between pages. The paginator is `disabled` while a page loads.

## Selection

The table has no selection input. A selection column is an ordinary consumer
column: a `mud-checkbox` per row plus a CDK `SelectionModel`. Add
`class="mud-data-table__selection-cell"` to its header and body cells for the narrow
width, and bind `[selected]` on the row (`<tr mud-row … [selected]="selection.isSelected(row)">`)
to paint it in the brand selection colour; it also sets `aria-selected` on the row.

## Row actions

Put actions in a trailing column. Use `mudIconButton size="small"` (a 32px circle
with a 16px glyph) and add `class="mud-data-table__actions-cell"` to that column's
header and body cells: the helper trims the block padding to 4px so the row keeps its
40px height. An icon-only button needs a per-row accessible name
(`[attr.aria-label]="'Editează ' + row.nume"`); the header keeps a visible label.
Register the icon once with `provideMudIcons([edit])` — the library never populates
the icon registry for you.

## Accessibility

- **Native `<table>` by default.** Use it whenever you can; screen readers get
  row and column navigation for free. The flex layout receives
  `role="table|row|columnheader|cell|rowgroup"` from the CDK.
- **Name the table** with `aria-label` or `aria-labelledby`.
- **Sortable headers are buttons.** Each `mud-sort-header` renders a native
  `<button>` whose name is the header text, described by a hidden "Sort" text
  (`sortActionDescription`; by default the `table.sort` label). The `<th>` carries `aria-sort`, so
  the column state is announced. Enter, Space and click all sort.
- **Direction is shown by shape, not colour.** Unsorted columns show the
  two-way grabber; the sorted column shows one chevron.
- **Scrollable wrappers need `tabindex="0"`** so keyboard users can scroll.
- **Selection is conveyed by the checkbox.** `selected` on a row adds `aria-selected`,
  which is valid on a table row but only reliably announced inside a `grid`; the
  per-row `mud-checkbox` is what screen readers use to tell selected rows apart.
- **Contrast** of every text/background pair is at least 4.5:1 in both themes;
  `table.contrast.spec.ts` pins the numbers.

## Usage tips

- **Column width:** every cell of a column gets `mud-column-<name>`; style it
  from your component (`.mud-column-suma { width: 120px }`).
- **Alignment is start everywhere.** Numbers are not right-aligned by design.
- **Keep `mudSort` on the table element** so the header cells find it.
- **`recycleRows`** is a CDK input (`<table mud-table recycleRows>`); do not
  combine it with row animations.
- **Padding tightens at ≤640px viewport** (24px → 16px), matching the design's
  mobile breakpoint.
