# File input

A field for choosing files, by dropping them or with a button, with a list of the chosen files. It
doesn't upload anything: you do that, and `mud-file-item` rows can show the progress. It works on its
own with `[(value)]`, with reactive and template-driven forms, and with signal forms.

```ts
import { MudFileInput, MudFileItem } from 'ngx-mud-ui/file-input';
import { MudInlineMessage } from 'ngx-mud-ui/inline-message';
import { MudLabel } from 'ngx-mud-ui/label';
```

## Basic

`value` is always a `File[]`, two-way bindable; without `multiple` it holds at most one file, and a
new pick replaces it. `accept`, `maxSize` (bytes) and `maxFiles` limit what's accepted, and the field
lists them under the drop zone. `accept` checks the type and extension only; check the contents on
your server.

Rejected files never enter the value. Each fires `rejected` with `{ code, file }`, where `code` is
`'type'`, `'size'` or `'count'`; show your own message from it. Image files get a preview
automatically.

## Variants and states

`variant` is `dropzone` (default) or `button`. `size` is `md` (default) or `lg`. `invalid`,
`required` and `disabled` work as in a [Text input](?path=/docs/components-form-text-input--docs).

## Reactive forms

Bind `formControl`: the value is the `File[]`, so `Validators.required` rejects an empty selection
and your validators see the real files. Bind `invalid` yourself.

## File rows

`mud-file-item` is the row the list uses, and works on its own:

- `state` is `uploaded` (default), `uploading` (a spinner; add `progress` from 0 to 100 for a bar),
  `success` or `error` (with `errorText`).
- `removable` (default `true`) shows a remove button that emits `removed`. While uploading, the same
  button cancels: stop your request there.
- An `[icon]` element replaces the file icon, for example per file type or a server thumbnail. For
  a server image, use `<img ngSrc>` there; `previewSrc` is for local previews only.
- `variant="system"` is for a document issued by the state: a grey card with an `[info]` line for
  the issue date and issuer.

## Uploading

Hide the built-in list with `[showFileList]="false"`, upload each picked file yourself and render
your own rows with `state` and `progress`. Here each file uploads with progress events, and removing
a row cancels its request. Files over 5 MB fail on purpose.

<Canvas of={FileInputStories.Upload} />

## Accessibility

- Added, removed and rejected files are announced. All texts (the drop zone text, button, captions,
  remove button and announcements) are translatable, or set per field with `ctaText`,
  `chooseFilesText`, `dropzoneActiveText`, `formatsCaption`, `maxSizeCaption`, `removeLabel` and the
  `announce*` functions.
- `required` adds the word "required" (`requiredLabel`) to the label for screen readers, since the
  browse button can't carry `aria-required`.
- Name the file list with `fileListLabel` when a form has several file fields; `""` leaves it
  unnamed.
- After a removal, focus moves to the next row, the previous one, or back to the browse button.

<ArgTypes of={MudFileItem} />

### Types

- `MudFileInputVariant`: `'dropzone' | 'button'`
- `MudFileInputSize`: `'md' | 'lg'`
- `MudFileInputRejectionCode`: `'type' | 'size' | 'count'`
- `MudFileInputRejection`: `{ code: MudFileInputRejectionCode; file: File }`
- `MudFileInputRemove`: `{ file: File; index: number; files: readonly File[] }`
- `MudFileItemState`: `'uploaded' | 'uploading' | 'success' | 'error'`
- `MudFileItemVariant`: `'default' | 'system'`
- `MudFileItemRemove`: `{ filename: string }`
