# Input chip

A field whose value is a list of strings. The user types, confirms with Enter or
a separator character, and each confirmed value becomes a removable chip.

## Import

```ts
import { MudInputChip } from 'ngx-mud-ui/input-chip';
import { MudLabel } from 'ngx-mud-ui/label';
import { MudInlineMessage } from 'ngx-mud-ui/inline-message';

@Component({
  imports: [MudInputChip, MudLabel, MudInlineMessage],
  template: `
    <mud-input-chip
      [maxChips]="5"
      [validatePattern]="emailPattern"
      [formControl]="recipients"
      [invalid]="recipients.touched && recipients.invalid"
    >
      <mud-label>Destinatari</mud-label>
      @if (recipients.touched && recipients.invalid) {
        <mud-inline-message variant="error">Adăugați cel puțin o adresă.</mud-inline-message>
      }
    </mud-input-chip>
  `,
})
export class Demo {}
```

The base stylesheet must be in your app's `angular.json` `styles` once:

```json
"styles": ["node_modules/ngx-mud-ui/prebuilt/mud.css", "src/styles.scss"]
```

### Label and messages

The field renders no message text of its own. Project a `<mud-label>` for
the visible label and any number of `<mud-inline-message>` elements for
assistive text — *you* decide when they render:

- Messages land in a field-owned `role="alert"` region wired into
  `aria-describedby`; toggling one on announces it to screen readers.
- Inside the field, `mud-inline-message` is always the small size — its
  `size` input is ignored.
- The field's `invalid` input drives the destructive border and
  `aria-invalid`; with signal forms it is bound automatically, with
  reactive forms bind `[invalid]="ctrl.touched && ctrl.invalid"`.

## Usage tips

- **`value` is the confirmed list; `draft` is the pending text.** They are
  separate two-way models, so text the user has typed but not confirmed never
  silently becomes part of the form value.
- **The validation input is `validatePattern`, not `pattern`.** That name is
  deliberate: signal forms auto-bind a member called `pattern` with an
  incompatible protocol (the field's own `readonly RegExp[]`), so using it here
  would collide.
- **Every rejection emits `errored`** with a code of `pattern`, `duplicate` or
  `max` — bind it to surface why a value was refused, since the field itself
  only clears the draft.
- **`separators` adds to Enter rather than replacing it**, and newlines always
  split a paste, so pasting a column of addresses works regardless of the
  setting.
- **Override the announcer and remove texts with functions.** `announceAdded`,
  `announceRemoved` and `announceRejected` build the live-region text, and
  `removeLabel` takes the chip's text and returns the remove button's name.
  Unset, the `inputChip` labels apply, so a language pack from
  `provideMudLabels` translates them. See the [Localization guide](?path=/docs/foundations-localization--docs).
- **`placeholder` only shows while the list is empty**, so it cannot be used as
  a persistent hint.
