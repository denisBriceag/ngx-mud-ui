# Date picker

`mud-date-input` is a date field: type the date, or pick it from a calendar that opens below. It
also takes a date range. `mud-date-picker` is the calendar on its own. Both work on their own with
`[(value)]`, with reactive and template-driven forms, and with signal forms.

```ts
import { MudDateInput, MudDatePicker } from 'ngx-mud-ui/date-picker';
import { MudInlineMessage } from 'ngx-mud-ui/inline-message';
import { MudLabel } from 'ngx-mud-ui/label';
```

## Basic

The value is an **ISO date string**, `YYYY-MM-DD`, or `null`; never a `Date`. A calendar day is a
date, not a moment in time, and a `Date` brings a time zone: `new Date(1990, 4, 15)` sent as JSON
becomes `"1990-05-14T21:00:00.000Z"` in Moldova, a day early. Most backends already send date-only
strings, so usually there's nothing to convert. A value that isn't `YYYY-MM-DD` shows as empty, with
a warning in development.

`clearable` adds a × button that emits `cleared`. The calendar opens from its button or with

<kbd>Alt</kbd>+<kbd>↓</kbd>, never on focus, so typing is never interrupted. `open` is two-way
bindable.

## Formats

`format` is `DD/MM/YYYY` (default), `MM/DD/YYYY` or `YYYY-MM-DD`; it sets how the date is typed and
shown, while the value stays ISO. `placeholder` is the pattern shown in the empty field and behind the
caret while typing. It must have the format's shape and separators, such as `ZZ/LL/AAAA` for
Romanian; anything else falls back to the format, with a warning in development.

## Range

`mode="range"` shows two inputs in one field, and the value is `{ start, end }`. After the start
date, focus moves to the end; <kbd>Backspace</kbd> at the start of the end input goes back. A range
entered the wrong way round is swapped. Screen readers hear each input as the field's label plus
"Start date" or "End date".

## Limits and unavailable days

`min` and `max` are inclusive ISO limits. `disabledDates` lists ISO dates that can't be picked, such
as holidays, and `dateFilter` returns `true` for the days that can, such as weekdays only. Unavailable
days are dimmed in the calendar and refused when typed. They never add a validation error to your
form; validation is up to you.

While typing, an incomplete or refused date leaves `value` as `null`. On blur, the field goes back
to the last date it held; clearing the field yourself is never undone.

## Header style and touch screens

`headerStyle="dropdown"` shows month and year buttons in the calendar header, so a date far away,
such as a birth date, takes two clicks instead of many pages. The default, `title`, shows "Month
Year" as one button.

The calendar always stays on screen: it opens below the field, or above when there's no room, and
narrows on phones. `touchUi` opens it as a centered dialog over a backdrop instead, with the
dropdown header by default. It never switches on by itself; bind it to a media query to use it on
small screens, as here. A change applies the next time the calendar opens.

## The calendar on its own

`<mud-date-picker>` takes `mode="single"` (an ISO string), `range` (`{ start, end }`) or `multi` (a
list of ISO strings). `appearance="flat"` removes the card shadow, to put it in your own surface.
`startAt` sets the month shown first without selecting anything, `showTodayShortcut` toggles the
"Today" button, and `monthChange` emits `{ year, month }` (month 0-based) as the user pages.

Clicking the header goes to a month grid, then a year grid of 12 years. It takes the same `min`,
`max`, `disabledDates`, `dateFilter`, `firstDayOfWeek` and `locale` as the field.

## Forms

Bind `formControl` and bind `invalid` yourself, or bind `[formField]` and let the field drive
`invalid` and `required`. The calendar on its own takes the same bindings.

## Language

Month and weekday names come from the browser (`Intl`) in the `locale` input, or the
[formatting locale](?path=/docs/foundations-localization--docs). All other texts (the Today button,
the arrows, the clear button, announcements) are in the `datePicker` labels. When `Intl`'s short
month names don't suit your design, set `monthNamesShort` and `monthNamesLong` there.
`firstDayOfWeek` is 1 (Monday) by default; 0 is Sunday.

## Dates in code

Helpers for the ISO strings:

- `mudToday()`: today, as `YYYY-MM-DD`.
- `mudAddDays(iso, days)`: a date a number of days later (or earlier, with a negative number).
- `mudDateFromDate(date)`: a `Date`'s local day as `YYYY-MM-DD`.
- `mudDateToDate(iso)`: a `Date` at local noon, which daylight saving can't push to another day.
  Don't use `new Date('2026-08-27')`: it reads the date as UTC midnight.

## Accessibility

- Messages and the format hint are linked with `aria-describedby`; messages sit in a `role="alert"`
  region, so showing an error announces it.
- In the calendar, the day grid is one <kbd>Tab</kbd> stop. Arrows move by day and week;
  <kbd>Page Up</kbd> and <kbd>Page Down</kbd> by month (with <kbd>Shift</kbd>, by year);
  <kbd>Home</kbd> and <kbd>End</kbd> to the start and end of the week; <kbd>Enter</kbd> or
  <kbd>Space</kbd> selects.
- <kbd>Esc</kbd> closes the calendar and returns focus to the field.
- `mud-date-picker` shows no messages; it only takes `invalid` for the error style and
  `aria-invalid`.

### Types

- `MudDateInputMode`: `'single' | 'range'`
- `MudDatePickerMode`: `'single' | 'range' | 'multi'`
- `MudDateValue<M>`: `string | null` (single), `MudDateRange | null` (range), `string[] | null` (multi)
- `MudDateRange`: `{ start: string | null; end: string | null }`
- `MudDateFormat`: `'DD/MM/YYYY' | 'MM/DD/YYYY' | 'YYYY-MM-DD'`
- `MudDatePickerHeaderStyle`: `'title' | 'dropdown'`
- `MudDatePickerAppearance`: `'elevated' | 'flat'`
- `MudDateMonthChange`: `{ year: number; month: number }`
- `MudDateInputSize`: `'md' | 'lg'`
- `MudDateInputVariant`: `'default' | 'warning' | 'destructive' | 'success'`
- `MudCivilDate`: `{ y: number; m: number; d: number }`
