# Tree

Hierarchical navigation, such as a sidebar menu: sections open to show their pages, and the current
page is highlighted. Built on the CDK tree; every row is a
[Tree item](?path=/docs/components-tree-item--docs), with the same look and slots.

```ts
import { MudTree, MudTreeNode, MudTreeNodeDef } from 'ngx-mud-ui/tree';
```

## Navigation

Pass the top-level items to `dataSource` and a `childrenAccessor` that returns an item's children.
Then write a row template with `*mudTreeNodeDef`. Write `let node of nav` (the same data as
`dataSource`) so `node` is typed in the template; without `of`, it isn't.

Use the element that matches what a row does:

- **A page** is a link, `<a mud-tree-node [routerLink]>`. Bind `selected` to `routerLinkActive`.
- **A section** is a button, `<button mud-tree-node>`; clicking it opens and closes it.

Several templates can be picked per item with `when`; the one without `when` is the default. Set
`[isExpandable]` on every row that has children: it shows the chevron and tells screen readers the
row opens. Only open sections are rendered.

<Canvas of={TreeStories.Navigation} />

## Pages with children

A page can have children too, like a settings page with sub-pages. Clicking it navigates and opens
it; only the chevron closes it, so arriving on the page never hides its children.

<Canvas of={TreeStories.PageParents} />

## Nesting

Sections nest to any depth; each level indents 32px more. The tree works out each row's level. It
only supports nested data through `childrenAccessor`, not flat data with `levelAccessor`.

<Canvas of={TreeStories.Nested} />

## Expanding from code

Get the tree with `#tree="mudTree"` or `viewChild(MudTree)` and call `expand(node)`,
`collapse(node)`, `toggle(node)`, `expandAll()` or `collapseAll()`.

<Canvas of={TreeStories.ExpandAll} />

## Row content

Rows take the same content as a tree item: `[icon]`, `[selectedIcon]`, `[secondaryLabel]` and
`[trailing]` (a badge or tag). The chevron comes after the trailing content. Give each slotted
element its own `@if`: Angular can only project an `@if` block that holds a single element.

<Canvas of={TreeStories.Badge} />

## Your own data

A node is any object, so add the fields your app needs (an id, a permission) to your interface. With
`let node of nav`, they're typed in the template too.

<Canvas of={TreeStories.CustomData} />

## Choosing several rows

For a list of choices such as filters, add `multiple` to the tree, keep the chosen items yourself and
bind each row's `selected` to them. Screen readers announce them as chosen (`aria-selected`) instead
of as the current page. Here each section's badge counts its chosen children.

<Canvas of={TreeStories.Multiple} />

## Disabled rows

`[isDisabled]` disables a row: it stays visible, can't be clicked, and the arrow keys skip it. A
disabled section doesn't open. Only `button` and `div` rows can be disabled; leave out a link that
isn't available.

<Canvas of={TreeStories.Disabled} />

## Accessibility

The tree follows the [ARIA tree view pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/).
Name it with `aria-label` or `aria-labelledby`; it warns in development without one.

- The whole tree is one <kbd>Tab</kbd> stop. <kbd>↓</kbd> <kbd>↑</kbd> move between visible rows.
- <kbd>→</kbd> opens a row or moves to its first child; <kbd>←</kbd> closes it or moves to its
  parent.
- <kbd>Home</kbd> and <kbd>End</kbd> go to the first and last row; a letter jumps to the next row
  starting with it; <kbd>*</kbd> opens all rows at the current level.
- <kbd>Enter</kbd> or <kbd>Space</kbd> follows a link, toggles a section or toggles a choice.
- `selected` sets `aria-current="page"`, or `aria-selected` in a `multiple` tree.
- A row's `(activation)` output fires only for <kbd>Enter</kbd> and <kbd>Space</kbd>; use `(click)` or
  `routerLink` to react to both mouse and keyboard.

## API

### MudTree

Selector: `mud-tree` · Exported as: `mudTree`

<ArgTypes of={MudTree} />

Inherited from the CDK's `CdkTree`:

- `dataSource` (input): the top-level items (an array, an `Observable` or a `DataSource`).
- `childrenAccessor` (input, `(node) => T[] | Observable<T[]>`): returns a node's children.
- `trackBy`, `expansionKey` (inputs): how rows and their open state are tracked.
- `expand(node)`, `collapse(node)`, `toggle(node)`, `isExpanded(node)`, `expandAll()`,
  `collapseAll()`, `expandDescendants(node)`, `collapseDescendants(node)`, `toggleDescendants(node)`.

### MudTreeNode

Selector: `a[mud-tree-node], button[mud-tree-node], div[mud-tree-node]` · Exported as: `mudTreeNode`

<ArgTypes of={MudTreeNode} />

Inherited from the CDK's `CdkTreeNode`:

- `isExpandable` (input, `boolean`): the row has children and shows a chevron.
- `isExpanded` (input, `boolean`): opens or closes the row.
- `isDisabled` (input, `boolean`): disables a `button` or `div` row.
- `expandedChange` (output, `boolean`), `activation` (output, the node).

Content slots: `[icon]`, `[selectedIcon]`, the label, `[secondaryLabel]` and `[trailing]`.

### MudTreeNodeDef

Selector: `[mudTreeNodeDef]`, used as `*mudTreeNodeDef="let node of data; when: predicate"`.

<ArgTypes of={MudTreeNodeDef} />

`when` (`(index, node) => boolean`) picks this template for the nodes it returns `true` for.
